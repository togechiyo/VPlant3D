# 腕平面twistリターゲット計画

確認日: 2026-05-28

## 背景

PoseLandmarkerの肩・肘・手首から前腕を動かす実装は、これまで主に以下の値で調整していた。

- 上腕の持ち上げ
- 上腕の横開き
- 前腕の肘曲げ
- 前腕の前方逃がし

しかし、VTuberのWポーズや顔前へ手を持ってくる動きでは、前腕だけでなく上腕のひねり、肩の回り込み、前腕の回内回外が合成されて見える。

そのため、前腕ボーンだけで向きを合わせようとすると、以下が起きやすい。

- 腕を外側へ上げても前腕が胸前へ巻き込む
- Wポーズで肘曲げが足りない
- 前腕を強く曲げると体に刺さる
- 係数調整が姿勢ごとに衝突する

## 方針

依存は増やさず、PoseLandmarkerの3点から腕平面を作り、上腕にもtwistを分担させる。

腕平面:

- `upper = shoulder -> elbow`
- `lower = elbow -> wrist`
- `planeNormal = cross(upper, lower)`

利用する値:

- `upperArmTwist`: 腕平面の向きから、上腕に入れる補助ひねり
- `forearmDirection`: 肘 -> 手首の向きから、前腕に入れる主方向
- `bend`: 肘角度から、前腕に入れる曲げ量

## 実装方針

1. `src/mocap/arm-ik-target.ts` に腕平面ベースの補助値を追加する
2. `ArmIkSideTarget` の既存payloadは維持する
3. `upperArmRotation.y` に腕平面由来のtwistを足す
4. 外側へ伸びる前腕では、内側へ畳む `z` 曲げを弱める
5. 内側・上側へ戻る前腕では、Wポーズとして `z` 曲げを強める
6. fallback payloadも同じ考え方に寄せる

## テスト観点

- Wポーズでは深い前腕曲げが出る
- 外側へ前腕を伸ばす姿勢では、内側へ強く折れない
- 腕平面が傾く姿勢では上腕twistが出る
- lowered armはほぼneutral
- mirror ON/OFFで左右が破綻しない

## 制約

- PoseLandmarkerのzはカメラ環境で不安定なため、twistは強くしすぎない
- 完全な手首位置IKは目標にしない
- ハッカソンMVPでは、破綻しにくい見た目を優先する

## 次の判断

この方式でも不自然さが残る場合は、係数調整を続けるより、VRMボーンのローカル軸可視化とモデル別キャリブレーションへ移る。
